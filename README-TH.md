# Finance Bot 2.1: รับสลิปด้วย Firebase เดิม

ชุดนี้เตรียมจากไฟล์ `finance-bot.zip` และ `finance-bot-railway.zip` ที่ส่งมา เป็นฉบับสำหรับเซิร์ฟเวอร์ Node.js บน Render หรือ Railway โดยคงเส้นทางรับข้อความ `/webhook` และหน้าแรกเดิมไว้

## สถานะ

โค้ดนี้ยังไม่ได้อัปเดตขึ้น Render หรือเขียนฐานข้อมูลจริง ทดสอบด้วยข้อมูลจำลองบนเครื่องแล้ว เจ้าของอนุญาตให้ใช้ Firebase เดิมกับส่วนรับสลิปใหม่ และเข้าสู่ Console ให้ตรวจแล้วเมื่อ 28 ต.ค. 2569

เจ้าของเลือกปิดการอ่านแบบสาธารณะทั้งหมดแล้ว เผยแพร่กฎ private บนโครงการจริงเมื่อ 28 ต.ค. 2569 สำเร็จ ตรวจด้วย GET ที่ไม่ส่งข้อมูลล็อกอินไปยังเอกสารหนี้เดิมและส่วนรับสลิปแล้ว ได้ HTTP 403 `Missing or insufficient permissions.` ทั้งสองเส้นทาง ไม่ได้แก้หรือลบเอกสารหนี้เดิม บอทและส่วนซิงก์รุ่นใหม่ยังไม่ได้ deploy

บัญชีที่ผู้ใช้เลือกคือ “คลุกฝุ่นทัวร์” (`@011xozve`) ซึ่งตรวจพบว่าเปิด Webhook ไปยัง `https://finance-bot-xwvv.onrender.com/webhook` อยู่แล้ว การเชื่อมแบบนี้ใช้ที่อยู่เดิมได้หลังอัปเดตโค้ด จึงไม่จำเป็นต้องสร้าง tunnel มาที่คอมพิวเตอร์ส่วนตัว

ตรวจ Render เมื่อ 28 ต.ค. 2569 แล้ว: บริการ `finance-bot` ใช้แพ็กเกจ Free ใน Singapore เชื่อม repository `Cabalistic6540/finance-bot` สาขา `main` เวอร์ชันที่กำลังรันคือ `d92be176b24ba8ec97d94a4581560f3515326143` เริ่มด้วย `node index.js` และติดตั้งด้วย `yarn install`

เวอร์ชันจริงใหม่กว่า ZIP: มี Claude อ่านรูป, Firebase Admin บันทึกยอดหนี้ และข้อความสลับโปรไฟล์ รุ่น 2.1 นี้เตรียมใช้ Firebase เดิมเก็บคิวและรูปถาวร มีตัวเลือกอ่านรูปด้วย Claude และแก้การเลือกโปรไฟล์จริง แต่ต้องตรวจสิทธิ์ฐานข้อมูลและตั้งค่าที่จำเป็นให้ครบก่อน deploy

แก้ข้อผิดพลาดของเวอร์ชันจริงในชุด 2.1 แล้ว: เดิมคำสั่งสลับโปรไฟล์ไม่ได้เก็บโปรไฟล์ที่เลือกและเรียก `saveToFirestore('ct', ...)` เสมอ รุ่นใหม่เก็บโปรไฟล์ถาวรต่อผู้ส่ง ผูกกับรูป ณ เวลารับ และป้องกันคำสั่งเก่าที่ส่งซ้ำย้อนโปรไฟล์ปัจจุบัน รูปสลิปเก็บเป็นรายการรอตรวจ ไม่เขียนยอดหนี้ทันทีหรือเอาจำนวนเงินที่โอนมาแทนยอดหนี้

ค่าบน Render ที่พบมี `CHANNEL_ACCESS_TOKEN`, `CLAUDE_API_KEY` และ `FIREBASE_SERVICE_ACCOUNT` ยืนยันเฉพาะชื่อโครงการจากค่าตั้งเดิมแล้วคือ `finance-bot-393c1` โดยไม่คัดลอก private key ออกมา ชุดนี้รองรับชื่อกุญแจสองตัวแรกเป็นชื่อสำรอง ใน Console พบ Firestore (default) อยู่ที่ asia-southeast3 บนแผน Spark และมี collection `debts` เดิม รุ่นใหม่ใช้ `financeReceiptInbox_v1` กับ `financeReceiptProfiles_v1` และ subcollection `imageChunks` ไม่เขียนทับ `debts`

ก่อนหมุนกุญแจ ตรวจเฉพาะ SHA-256 แล้วพบว่า Channel access token บน Render ตรงกับตัวในประวัติ GitHub สาธารณะรุ่น `8dbaa03` (ไม่ใช่ตัวใน ZIP) เจ้าของออกกุญแจใหม่ผ่าน LINE Developers แล้ว และอนุญาตให้บันทึกแทนค่าเดิมใน Render เมื่อ 28 ต.ค. 2569 ตรวจลายนิ้วมือค่าที่บันทึกแล้วตรงกับกุญแจใหม่ โดยไม่ใส่ค่ากุญแจในแชท ไฟล์โค้ด หรือ repository

Render เริ่มเวอร์ชันเดิม `d92be17` ใหม่ด้วยกุญแจใหม่สำเร็จใน deployment `dep-dbgk0i88v5cc73ft6gh0` (Environment updated) ตรวจหน้าแรกได้ HTTP 200 และข้อความบริการที่คาดไว้ ส่วนโค้ดรับสลิปรุ่น 2.1 ยังไม่ถูกส่งขึ้น GitHub/Render เตรียม working copy จาก commit เดิมที่ `finance-bot-deploy` บน branch `codex/firestore-receipt-sync` และทดสอบชุดที่จะส่งผ่านแล้ว รอการเชื่อมบัญชี GitHub ที่ยืนยันเพื่อส่งโค้ด

## การทำงาน

1. LINE ส่งเหตุการณ์มาที่ `/webhook`
2. บอทตรวจลายเซ็นด้วย Channel secret และรับเฉพาะรูปที่เจ้าของส่งจากห้องส่วนตัวตาม user ID ที่กำหนด
3. บันทึกคิวใน Firestore ก่อนตอบรับ LINE จากนั้นดึงรูปมาเก็บเป็นส่วนย่อยไม่เกิน 512 KiB เมื่อครบและตรวจ hash แล้วจึงประกาศว่ารูปพร้อม มีการลองใหม่ ป้องกันรับรูปซ้ำ และ lease ป้องกันบอทสองตัวประมวลผลรูปเดียวกันพร้อมกัน
4. แอพบนเครื่องใช้กุญแจซิงก์ดึงรูปผ่าน `/finance/receipts` และ `/finance/receipts/<id>/image` ทุก 5 วินาทีขณะตัวรันแอพเปิดอยู่
5. คุณอ่านข้อความในแอพ ตรวจยอด วันที่ หนี้ และงวด แล้วยืนยันก่อนบันทึกการจ่าย

รูปที่เข้าคิวแต่ยังดึงไม่สำเร็จจะแยกสถานะรอและผิดพลาด ไม่ถูกนับว่าเป็นรายการชำระแล้ว ตัวบอทไม่ได้สั่งโอนเงินและไม่ได้เข้าถึงแจ้งเตือน KBank ใน LINE ห้องอื่น

คำสั่ง `โปรไฟล์โตส` / `ctos` และ `โปรไฟล์ขวัญ` / `kwan` เลือกโปรไฟล์สำหรับรูปถัดไป หน้าบันทึกจ่ายในแอพปัจจุบันรองรับเฉพาะโตส สลิปขวัญเก็บแยกและปิดปุ่มบันทึกเข้าหนี้โตส ยังไม่มีหน้าบันทึกจ่ายของขวัญ

Firestore listener ติดตามข้อมูลคิวที่เปลี่ยน ไม่ query ข้อมูลทั้งหมดใหม่ทุกครั้งที่แอพถามสถานะ รูปถูกอ่านเมื่อต้องส่งให้แอพ ยังมีการใช้โควตาพื้นที่ อ่าน และเขียนตามปริมาณจริง ไม่ควรเปิด billing หรือเพิ่มบริการโดยไม่ให้เจ้าของยืนยัน

## ค่าที่ต้องตั้งใน Render

- `LINE_CHANNEL_ACCESS_TOKEN`: กุญแจของ OA นี้
- `LINE_CHANNEL_SECRET`: สำหรับตรวจลายเซ็น ต้องเป็นช่อง Messaging API เดียวกัน
- `LINE_ALLOWED_USER_IDS`: Your user ID ของเจ้าของแอพ ถ้ามีหลายคนให้คั่นด้วยจุลภาค
- `FINANCE_SYNC_TOKEN`: กุญแจสุ่มอย่างน้อย 32 ตัว เก็บค่าเดียวกันในช่อง “กุญแจซิงก์” ของแอพบนเครื่อง ห้ามใส่ในโค้ดหรือ URL
- `FINANCE_STORAGE=firestore`: บน Render ต้องใช้ Firestore ไม่มีการถอยไปเก็บไฟล์ชั่วคราวเองเมื่อ Firebase มีปัญหา
- `FIREBASE_SERVICE_ACCOUNT`: ใช้ค่าเดิมใน Render ไม่ใส่ private key ใน repository
- `DATA_DIR`: ใช้เฉพาะการทดสอบแบบ `FINANCE_STORAGE=file` บนเครื่อง
- `PORT`: Render กำหนดให้อัตโนมัติ

ใช้ Node.js 22 ขึ้นไป ติดตั้งด้วย `npm ci --omit=dev` จาก package-lock.json เริ่มด้วย `npm start` หรือ `node index.js` ใช้ Firebase Admin SDK 14.5.0 ซึ่งตรวจ npm audit แล้วไม่พบช่องโหว่ ณ วันที่จัดชุด ไม่เพิ่ม SDK หรือ service-account key ไว้ในหน้าเว็บ

Render ใช้ระบบไฟล์ชั่วคราวโดยปริยาย รุ่นนี้เก็บคิวและรูปใน Firestore เดิม จึงไม่ต้องเพิ่มดิสก์หรือเปลี่ยนแพ็กเกจ Render ตัวบอทปฏิเสธการเริ่มด้วย file mode เมื่อ `RENDER=true` ยังต้องตรวจ Firestore Rules และโควตาจริงก่อนใช้รูปจริง

Firestore Rules ต้องป้องกัน client ที่ไม่ได้รับสิทธิ์อ่านหรือเขียนสอง collection ใหม่ รวมถึงรูปใน subcollection บอทใช้ Admin SDK จึงไม่ต้องเปิด public read/write การเพิ่ม deny แยกจะไม่ช่วยหากมีกฎ allow ที่ครอบคลุมทุก path อยู่ ต้องตรวจ rules เดิมทั้งชุดก่อนแก้

ก่อนแก้ Rules พบ `allow read: if true` ครอบคลุมทุกเอกสาร และ `allow write: if false` เก็บสำรองที่ firestore.previous.rules เจ้าของเลือกและอนุญาตเผยแพร่ firestore.private.rules แล้ว ซึ่งปิด client read/write ทั้งหมดและให้บอทใช้สิทธิ์ Admin SDK เดิม แอพ Claude รุ่นเก่าที่อ่าน Firebase โดยตรงจะอ่านไม่ได้ ไม่ควรนำไฟล์ previous หรือทางเลือก keep-legacy กลับไปเผยแพร่โดยปริยาย

จำลอง get โดยไม่เข้าสู่ระบบที่ `financeReceiptInbox_v1/verification-only` ได้ `Simulated read denied` ก่อนเผยแพร่ จากนั้น Publish ตามที่เจ้าของเลือกและตรวจ anonymous GET กับกฎที่ใช้งานจริงได้ 403 แล้ว ไม่มีการสร้างเอกสารทดสอบในฐานข้อมูล

ข้อมูลหนี้เดิมใน Firebase ลงวันที่ มิ.ย.–ก.ค. 2569 บางรายการไม่ตรงข้อมูลล่าสุดจาก Excel/ภาพหน้าจอ จึงไม่ดึงมาทับข้อมูลล่าสุดในแอพโดยอัตโนมัติ

เก็บกุญแจไว้ในการตั้งค่าของเซิร์ฟเวอร์ ชุดนี้ไม่มีค่ากุญแจจากไฟล์ต้นฉบับ หากกุญแจเดิมเคยเผยแพร่สู่สาธารณะ ให้ประเมินการเปลี่ยนกุญแจและผลกระทบต่อบอทเดิมก่อนใช้งานต่อ

## ความสามารถเดิมจาก ZIP

การอ่านรูปด้วย Claude และตอบกลับใน LINE เป็นตัวเลือก ไม่เปิดเองในชุดนี้:

- ตั้ง `LEGACY_ANALYSIS_ENABLED=true`, `ANTHROPIC_API_KEY` และ `ANTHROPIC_MODEL` เมื่อเจ้าของต้องการใช้บริการนั้นต่อ ภาพจึงจะถูกส่งไป Anthropic และอาจมีค่าใช้บริการตามบัญชี
- ตั้ง `LINE_REPLY_ENABLED=true` เมื่อต้องการข้อความตอบรับและผลอ่านรูปกลับทาง LINE
- ค่าเริ่มต้นทั้งสองส่วนคือ `false` ส่วนรับรูปและส่งให้แอพทำงานได้โดยไม่ใช้ Claude ส่วนจัดเก็บบน Render ใช้ Firebase เดิม
- โค้ดตัวอย่างนี้ไม่รองรับแชทกลุ่ม และไม่เพิ่มสิทธิ์ให้ผู้ส่งอื่นโดยอัตโนมัติ

## เชื่อมกับแอพ

หลังตรวจโค้ดเดิมและอัปเดต Render แล้ว เปิด “บันทึกจ่าย / สลิป” ในแอพ เลือกส่วน “ต่อกับบอทเดิมของคลุกฝุ่นทัวร์” กรอก `FINANCE_SYNC_TOKEN` แล้วกดตรวจและเปิดดึงสลิป

กุญแจซิงก์เก็บบนเครื่องฝั่งตัวรัน ไม่ส่งกลับไปที่หน้าเว็บ หากบอทยังเป็นโค้ดเก่า แอพจะแจ้งว่าต้องอัปเดตบอทก่อน ไม่แสดงว่าเชื่อมสำเร็จ

การบันทึกจ่ายและยืนยันในแอพยังเก็บในเบราว์เซอร์นี้ รอบนี้ยังไม่ได้เพิ่มการซิงก์ประวัติการจ่ายข้ามอุปกรณ์หรือเขียน Excel อัตโนมัติ

## ตรวจสอบก่อนนำขึ้นจริง

ใช้ `npm test` ตรวจลายเซ็น ผู้ส่ง การรับซ้ำ การเลือกโปรไฟล์ข้ามการเริ่มใหม่ lease ระหว่างบอทสองตัว และการรับรูปที่ขาดกลางทาง การทดสอบ Firestore ใช้ตัวจำลองสัญญา SDK ในหน่วยความจำ ไม่ใช่การยืนยันสิทธิ์หรือโควตาโครงการจริง ตรวจการ import/API ที่ต้องใช้กับ SDK จริงที่ติดตั้งแล้วด้วย แต่ยังต้องทดสอบกับโครงการหลังตรวจสิทธิ์ครบ

ก่อนอัปเดตบริการ ให้ตรวจชื่อ repository/branch ของบริการที่ใช้อยู่ ค่าที่ตั้งไว้ และวิธีเก็บข้อมูลถาวร เก็บสำรองโค้ดเดิมก่อนนำส่วนซิงก์นี้ไปผสาน และทดสอบการรับสลิปหนึ่งรายการหลังอัปเดตโดยให้เจ้าของเป็นผู้ส่ง
